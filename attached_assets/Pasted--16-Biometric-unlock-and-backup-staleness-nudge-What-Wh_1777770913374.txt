#16 - Biometric unlock and backup-staleness nudge
What & Why
Two unlock/UX improvements. Biometric: typing a PIN every time the app opens is friction; phones already unlock with Face ID / fingerprint. Use the browser's Passkey / WebAuthn API so the device biometric unwraps the encryption key. Nudge: notaries forget to back up. A small banner if the last Drive backup is over 7 days stale (configurable) prevents the worst-case "I lost my phone and lost two months of entries" scenario.

Done looks like
Settings has an "Enable biometric unlock" toggle. Turning it on prompts the device biometric (Face ID / fingerprint / Windows Hello / Touch ID) and stores a wrapped copy of the encryption key locked behind that biometric.
On launch, if biometric is enabled, the lock screen offers "Use Face ID" (or generic "Unlock with biometric") as the primary action with PIN as fallback.
If the device doesn't support WebAuthn / platform authenticators, the toggle is hidden with a brief explanation. Browsers tested: Chrome (Android/desktop), Safari (iOS/macOS), Firefox (desktop), Samsung Internet.
Disabling biometric or changing the PIN invalidates the wrapped key.
Dashboard shows a yellow banner reading something like "Your last backup was 12 days ago — back up now?" when the configured threshold is exceeded.
Settings → Cloud Backup has a "Remind me if backup is older than [3 / 7 / 14 / 30] days" dropdown.
The banner has "Back up now" (triggers Drive backup) and "Dismiss for today" (snoozes 24h) buttons.
If Drive isn't connected at all, the banner instead reads "You haven't set up cloud backup. Set it up?" with a link to Settings → Cloud Backup. Same snooze.
Vitest covers: staleness threshold logic (boundary cases), snooze persistence, and biometric-key wrapping/unwrapping round-trip (mocked WebAuthn).
Out of scope
Server-side biometric (we have no server).
Recovery of biometric without PIN — losing the PIN still wipes biometric.
Cross-device biometric sync.
Steps
WebAuthn wrapper — Helper module that creates a platform credential, generates a key-wrapping key from it, wraps the in-memory encryption key, and stores the wrapped blob in IndexedDB.
Lock screen update — Detect biometric availability; show "Unlock with [biometric]" button as primary action. On success, unwrap the key, decrypt the canary, and unlock.
Settings toggle — Add the on/off switch with the right copy explaining the trade-off (faster but device-bound).
Staleness banner — Read gdrive_last_backup (already stored), compare to threshold, render a dismissible banner on Dashboard. Snooze stored in IndexedDB (per-day key).
Threshold setting — Dropdown in Cloud Backup section.
Edge cases — If user has Drive enabled but never completed a backup, show the same banner. If they explicitly opted out of cloud backup (new "I'll handle backups manually" preference), respect it and don't nag.
Critical constraints
Builds on the foundational data security task's encryption. The biometric wraps the same encryption key derived from PIN — it doesn't replace the PIN, it caches it.
Must be 100% no-backend. WebAuthn calls go directly to the platform authenticator.
